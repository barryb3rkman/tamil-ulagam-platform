# Tamil ID Page Composition

## Purpose and positioning

The Tamil ID page is a permanent public explanation of a planned Tamil Ulagam membership credential. It positions Tamil ID as a future connection to an approved membership record, chapters, organisations, events and member experiences. It does not represent a live product, application process or verification service.

Tamil ID is explicitly not a government identity document, passport, citizenship record, payment card or replacement for official identification.

## Content sequence

The page moves from a concept-preview hero through definition and boundaries, a proposed membership journey, credential anatomy, verification and privacy, future access, governance, staged rollout, frequently asked questions and a partnership-oriented closing call to action. This order explains trust requirements before future access opportunities.

## Verification and privacy

The illustrative verification URL is a non-functional format only. The proposed model keeps sensitive personal data out of QR content and limits public verification output to policy-approved information. Public and private information are shown in separate, clearly labelled lists. Proposed membership states are not represented as operational records.

## Image, responsive and accessibility approach

The approved `tamilIdShowcase` registry entry is used once as the priority hero image. Its registered dimensions, alternate text and object position are retained. No second large credential image or unrelated initiative image is introduced. The editorial hero stacks copy and media on smaller screens; journeys, lists and rollout phases move from multi-column grids to readable linear sequences.

The page uses one h1, semantic sections, ordered journeys and rollout phases, a definition-list FAQ, visible text statuses and conventional links. Static FAQ content avoids unnecessary client-side interaction. Existing focus states and reduced-motion-safe CSS transitions are retained.

## Metadata and performance

Route metadata uses the approved credential showcase as the social image and provides a unique canonical title and description. The page is statically generated, does not add dependencies or a QR library, and uses no animation framework. Animation remains limited to existing button and focus transitions.
